# PiForge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build PiForge — a code-first toolkit to design, simulate, validate and export Raspberry Pi
devices (electronics + 3D-printed mechanics + firmware), with a web GUI (3D viewer, SPICE with
inputs, interactive digital twin).

**Architecture:** Python package `piforge` (src layout) with strictly layered subpackages
(core → fab/render/elec/spice/twin → mech → analysis → project/build/cli/server). build123d is used
only in `mech`/`analysis`/`project`; everything else is OCP-free and fast to test. GUI = FastAPI +
vanilla ES-module frontend with vendored three.js.

**Tech Stack:** Python 3.12, build123d 0.13 (OCP 8), trimesh 5 + manifold3d + embreex, numpy/scipy,
matplotlib, Pillow, ngspice 47, gpiozero 2, FastAPI/uvicorn, typer, pytest, Playwright, three.js
0.186, uPlot 1.6.

**Spec:** `docs/superpowers/specs/2026-10-04-piforge-design.md` (read it first; section numbers below
refer to it).

## Review Focus

1. **Paths with spaces/unicode** (the repo path has spaces and `~`): ngspice runs, twin runner
   subprocesses, exports and the server must work there. Owner tests: Task 5 (spice runner in a
   `tmp_path / "dir with spaces"`), Task 6 (runner with firmware in a spaced dir), Task 2 (export to spaced dir).
2. **Boolean cutters flush with faces** (coplanar faces → non-manifold/sliver geometry): every cutter
   helper extends through faces by ≥ 0.01 mm and exports must be watertight. Owner test: Task 2
   (`test_flush_cut_stays_watertight`), Task 3 (enclosure base/lid watertight).
3. **Misbehaving firmware** (infinite loop, exception, unsupported import such as `cv2`): the twin
   reports a clear error, `stop()` kills the runner within 2 s, server stays alive. Owner: Task 6.
4. **Pin naming variants** (`"GPIO17"`, `"gpio17"`, `"BCM17"`, `"pin11"`, `11`, `"GND"` many times):
   resolve consistently; an invalid name raises `PinNotFoundError` listing close matches. Owner: Task 4.
5. **Invalid simulation inputs** (R = 0, negative C, non-convergence): `SpiceError` with log excerpt;
   bench API validates ranges before running; GUI shows error without hanging. Owner: Task 5, Task 9.
