# _template

A PiForge project: a Raspberry Pi on a 3D-printed mounting plate, with a push button that toggles
an LED. Created with `piforge new`; edit `project.py` and `firmware/main.py` to make it yours.

## Files

| Path | What it is |
|---|---|
| `project.py` | `build(p)` describes the device: circuit, printed parts, assembly, firmware, scenarios, SPICE |
| `firmware/main.py` | Python firmware (gpiozero) — runs on the Pi and, unmodified, in the digital twin |
| `build/` | generated by `piforge build` (do not edit; safe to delete) |

## Commands

```sh
piforge check projects/_template          # fast checks: ERC, power, printability, assembly, twin wiring
piforge build projects/_template          # parts (STL/3MF/STEP), renders, BOM, wiring, pinout, report
piforge build projects/_template --scenarios   # … and run the twin scenarios too
piforge twin run projects/_template       # run the firmware on the virtual Pi, stream its log
piforge twin test projects/_template      # run the scenarios: pass/fail per scenario
piforge print projects/_template          # print time, filament and printability per part
piforge serve projects/_template          # browser GUI: 3D view, checks, SPICE, interactive twin
```

## What to look at after a build

- `build/report.md` — every finding (errors first) with a fix hint; exit code 1 when there are errors.
- `build/renders/assembly_sheet.png` — four views of the assembly with its overall size.
- `build/elec/wiring.png`, `wiring.md`, `pinout.md`, `bom.md`, `config.txt` — wiring and parts list.
- `build/parts/` — printable files in print orientation; `index.json` has the printability analysis.
- `build/sim/` — SPICE results (`status_led.png`: LED current through the 330 Ω resistor).

## The circuit

| Pi pin | Net | To |
|---|---|---|
| GPIO17 (pin 11) | button input, internal pull-up | SW1 → GND |
| GPIO27 (pin 13) | LED drive | R1 330 Ω → D1 (red LED) → GND |
